# Studio editor UX refinement

The existing macro architecture remains: permanent left rail; Project Tools, Preview, and one AI/context panel above a timeline that starts after the rail. The original reference informed internal hierarchy and composition; Blynta's theme, fonts, branding, icon system, and functionality remain.

## Requested report

1. **Visual audit:** The current screenshot showed disconnected form-like preview selectors, left-heavy transport, cramped timestamps, small headings and track labels, nested media filters, clipped AI suggestions, an oversized textarea with detached scope/send controls, weak clip hierarchy, and unclear icon actions. The original reference grouped controls and gave primary content stronger prominence. Both images were inspected before editing.
2. **Preview workspace:** One continuous surface with a quiet toolbar, centered canvas, dedicated seek row, and balanced transport. Canvas shadow and unnecessary internal borders were removed. The preview still occupies the existing center column.
3. **Toolbar:** Zoom and aspect ratio form one left-hand group using compact ghost-button dropdowns; aspect labels are simply `16:9`, `9:16`, `1:1`, or `4:5`. A subtle Preview label occupies the middle. Read-only 30 fps information is in the information popover. Working controls use shared dropdown/popover and compound tooltip primitives.
4. **Canvas sizing:** Padding decreased from 16 px to 8 px per side. The canvas continues to use the largest rectangle that fits both available dimensions at the project ratio. Landscape canvases fill width when width is limiting; portrait canvases fill height. Source contain/crop and transforms remain independent. A fullscreen sizing fix also fits the canvas while actual-size zoom is selected. Wide displays still have side whitespace when height limits a landscape canvas; the content is never stretched.
5. **Playback:** New Studio-specific PlaybackControls composes existing shared buttons, sliders, and tooltips around unchanged callbacks. Left: readable tabular time and volume. Center: frame back, prominent play/pause, frame forward. Right: fit and fullscreen. Seek has its own row. A volume slider is available on hover or keyboard focus. Narrow preview widths stack the transport groups instead of colliding.
6. **Blynta AI:** Explicit header/content/composer zones replace legacy form-like styling. The compact header uses a 14 px title and 12 px subtitle. The middle scrolls independently and contains readable empty-state guidance, a consistent two-column suggestion grid, conversation, pending proposals, applied results, and request/error status.
7. **Composer:** Prompt, scope, and circular send action share one rounded surface. The prompt starts at 48 px and grows to a bounded 104 px. Scope is integrated as a quiet control below the text. The footer is fixed in the panel layout. Shortcut instructions moved from a cramped visible line to the send tooltip and accessible description. Existing Enter/Shift+Enter and input shortcut guards remain.
8. **Proposal UX:** Pending proposals state the number of changes, list real operation descriptions, and expose Apply/Discard. Applied proposals show the applied count and Undo. Conversation messages and proposal surfaces have distinct indentation and treatment. Existing snapshot checks, stale-proposal protection, grouped undo, cancellation, API requests, and proposal history are unchanged.
9. **Project Tools:** A readable title with a secondary mode badge; search on a quiet background; source tabs with an underline; secondary media-type filters as borderless, neutral pills; a distinct Upload action. Media uses 16:9 thumbnails, overlaid duration badges, readable titles and type metadata, hover/selection treatment, and a drag cursor. Existing media upload, filtering, drag/drop, rename, removal, and reattachment remain.
10. **Timeline:** Toolbar height is 48 px, ruler height 36 px, rows 64 px, and clips 52 px. History and edit actions are separated; layer/snapping and time/zoom actions form the right group. Every existing timeline icon action has a shared tooltip. Track controls use a 192 px desktop column and 144 px mobile column, inline labels and secondary controls. A stronger playhead and subtle time grid give the remaining timeline area an intentional editing surface. The clip engine, source thumbnails, selection, trims, drag, snapping, split, duplicate, delete, and history are preserved.
11. **Typography:** Section titles use 14 px; normal controls, helper text, transport, ruler, and track labels generally use 12 px; media titles use 13 px; secondary badges and rail labels use 11 px. Clip text is 12 px. Timestamps use tabular numbers. This is a hierarchy, not a uniform enlargement.
12. **Spacing:** Panel content follows 12/16 px padding, 8/12 px group gaps, and 32 px toolbar icon controls. Small secondary track actions use shared 28 px icons. The rail has 20 px icons and consistent item spacing. Resize grips become more visible on hover/focus while retaining pointer and keyboard behavior.
13. **Borders:** Removed standalone preview form borders, canvas shadow, visible title-field border/background, nested filter boxes, AI suggestion outlines, separate scope-selector borders, and the textarea's own border. One composer boundary and actual panel/ruler/track separators remain. No custom stylesheet was introduced or edited.
14. **Shared UI:** Reused AppButton, AppInput, AppTextarea, AppTabs, AppSidebarItem, AppTooltip/TooltipTrigger/TooltipContent, AppDropdown, AppPopover, AppSelect, AppSlider, AppScrollArea, AppSkeleton, AppMediaCard, and existing media dialog/menu/file controls. No duplicate generic primitive or dependency was added. The shared PlayerControls implementation remains unchanged for other products.
15. **Studio components:** Refined EditorToolbar, EditorLoading, EditorToolRail/MediaPanel, MediaItem, PreviewCanvas, AIPanel/AIProposalResult, Timeline, and TimelineClip. Added the product-specific PlaybackControls composition. EditorShell only received resize-handle presentation changes in this refinement; its hierarchy stayed intact.
16. **State:** No new project, persistence, backend, auth, or API state model. Existing preview zoom, volume, fullscreen state, AI scope, prompt, and proposal state still drive the controls. UI tooltip/dropdown open state is handled by shared primitives. Layout preference dimensions and storage remain as established by the macro pass.
17. **Skeleton:** Updated the preview toolbar/canvas/seek/three-group transport; AI header/suggestions/anchored composer; timeline toolbar/ruler/larger track rows and wider control column. The permanent rail and original macro regions remain represented, including narrower mobile sizing.
18. **Responsive validation:** Browser checks cover 1280, 1440, 1600, and 1920 px, plus 2560, 1000, 768, 640, and 390 px. Checks assert track alignment, no page overflow, no overlap between transport groups, visible AI suggestions, composer anchoring through multiple proposals, source fit, portrait/landscape ratio controls, actual-size/fit/fullscreen, resize persistence without autosave, input shortcut safety, naming/autosave, clip history, AI apply/undo/discard, and export. Final screenshots at all requested desktop widths were inspected visually; a 1252 × 786 comparison capture matches the reference viewport.
19. **Files:** `apps/studio/features/studio/editor/components/{EditorToolbar,EditorShell,EditorLoading}.tsx`; `preview/{PreviewCanvas,PlaybackControls}.tsx`; `ai/AIPanel.tsx`; `media/{MediaPanel,MediaItem}.tsx`; `timeline/{Timeline,TimelineClip}.tsx`; `apps/studio/scripts/test-workspace.mjs`; this report and the link from the prior macro report. The test fixture uses the existing Blynta `northern-light.svg` artwork rather than the reference's media.
20. **Lint:** Studio ESLint passed.
21. **Typecheck:** Studio TypeScript check passed.
22. **Build:** Next.js production build passed using the documented process-only `MAIN_APP_URL=https://app.blynta.com`. No environment, font, auth, or API configuration was changed.
23. **Limitations:** UI tests use a synthetic session and mocked API responses; they do not verify live backend rendering or production SSO. Existing legacy CSS still supplies some inspector, media-layer, and clip internals, while all new refinements use Tailwind and semantic tokens. No real waveform generation or unsupported AI operation was invented. Short projects naturally have unused timeline time/rows; the grid makes that space purposeful. Narrow screens retain the existing contextual overlay model.

Pure editor regression checks also passed history, immutability, splitting and synchronized trims, transcript captions, grouped AI undo, serialized autosave, revision conflicts, and signed-URL stripping. Browser tests preserve and exercise those behaviors through the refined controls. The mock now returns unique proposal IDs so multiple real conversation entries can be tested independently.
