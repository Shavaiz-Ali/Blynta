# Studio editor functionality and targeted UX refinements

The approved shell, rail, Project Tools, preview, AI dock, timeline layout, and panel proportions are preserved. This pass changes the existing editor state and interactions; it adds no parallel timeline, backend changes, or auth changes.

1. **Library drag/drop root causes.** A baseline native browser drag onto an existing compatible lane succeeded: its custom asset ID reached the drop handler. The failure was not universal. The audit found hardcoded destination IDs in `makeClip`/`addAsset` without corresponding track creation, inconsistent incompatible-track handling, no insertion feedback, and unrestricted overlap on additions. A second clip could visually obscure the first instead of appearing as a sequential edit. Native thumbnail drags also advertised browser image/file payloads. The new flow uses an explicit asset drag source and validates actual track/model compatibility before placement.
2. **Drag/drop changes.** The shared media button carries the native drag payload, sets copy behavior, and records transient dragged-asset identity in the existing editor context. Nested images/video are not independent drag sources. The source dims while dragging. A valid lane gains a subtle themed outline and a time/track insertion marker; invalid or locked targets use a rejected drop cursor. Hover and commit use the same placement function. A nearby placement hint remains readable when collision resolution places the actual insertion point far away, and the selected addition is brought into view after drop. Preview drops prioritize the library asset ID before external file upload.
3. **Multiple assets.** Each accepted addition appends a distinct clip without replacing existing clips or creating a video track per asset. The new clip is selected. Sequential video, image, and audio additions use the current document/reducer. No library multi-selection existed; group selection/drag was intentionally not introduced.
4. **Drop position.** `timelineTime(clientX, contentRect.left, pixelsPerSecond)` converts pointer X to seconds. The content rectangle already reflects horizontal scrolling, so the offset is applied once. Existing half-second snapping is retained. The marker displays the resolved position, including collision adjustment. Placement rejects invalid metadata and timeline overflow.
5. **Tracks.** Compatible requested tracks are reused. Otherwise media routes to an existing compatible unlocked track, preferring the canonical main track. Images use visual/video tracks; audio uses audio tracks. A matching track is created atomically only when that media kind has no existing compatible track. Locked tracks are not bypassed by creating duplicates. Existing clip-based track visibility exposes newly populated tracks. Existing backend limits remain respected.
6. **Collision behavior.** Library additions move after intersecting clips on the destination track, repeating through subsequent intersections until there is room. Existing clips do not move, ripple, or disappear. Text/caption timing retains the existing semantics. Existing manual clip movement retains the engine's overlap/compositing behavior.
7. **Undo/redo.** Addition, asset metadata, and any required track creation are one existing reducer edit. Undo removes that edit; redo restores it. Pointer movement still commits once at gesture completion and remains undoable. No separate history mechanism was added.
8. **Autosave.** Reducer edits feed the existing `SaveSession`, revision checks, serialization, and API transport. Drag handlers make no direct persistence requests. Refreshed asset metadata is retained with additions, preventing clips from referencing stale zero-duration metadata. Signed URLs remain excluded by the existing serializer.
9. **Library grid.** The asset area uses Tailwind `grid-cols-2 gap-2` within the existing internally scrolling `AppScrollArea`. The panel's existing 260px minimum supports two compact thumbnails. Titles/types remain absent from normal card content; tooltips and accessible button names retain names. Video-only duration badges remain. Processing/unavailable media cannot be dragged; thumbnail failures use the existing media-kind icon fallback.
10. **AI button.** Composed the existing `AppButton` with the existing `WandSparkles` icon, a low-opacity theme gradient, and a slow 14-second background-position animation. An open-panel ring distinguishes open state from hover. Shared focus/disabled behavior remains; reduced-motion receives the static gradient. Export retains the solid primary treatment.
11. **AI colors.** The gradient derives only from `primary`, `chart-4`, and `secondary`. Border, icon, and open ring use `primary`. The tiny animation token/keyframes live in `packages/ui/src/styles/theme.css`; no Studio-specific CSS file or new palette was added.
12. **Preview zoom.** The compact transport Fit control is now a shared-dropdown composition offering Fit, 25%, 50%, 75%, 100%, 150%, and 200%. The duplicate two-option top-toolbar zoom control was removed; canvas aspect ratio remains there. Fit uses the available viewport and project aspect ratio. Percentages scale the existing logical 720px-height preview model; 16:9 at 100% is 1280×720. Larger views scroll inside the preview. Ctrl/Cmd-wheel over the canvas changes zoom. Entering fullscreen begins with Fit; zoom can still be changed in fullscreen. Zoom is local view state and never modifies document resolution, ratio, clip transforms, exports, or autosave. Browser/app Ctrl/Cmd-0/1 shortcuts were left untouched.
13. **Theme root cause.** Studio resolves React 19.2.8 and its own `next-themes` installation, while shared UI resolves React 19.2.4 and a different `next-themes` installation. Provider and shared controls therefore used different context instances. The development badge additionally covered the rail control; a persisted Next development-tools position overrode its configured position during browser testing.
14. **Theme fix.** Added `AppThemeProvider` to shared UI, re-exporting the existing `next-themes` provider from the same package instance used by shared controls. Studio's existing root provider now imports it, preserving the same `theme` preference key, system default, light/dark/system options, hydration strategy, and root-class Tailwind approach. There is no editor-only theme state. Development indicator placement is configured bottom-right; the test fixture also sets the ignored persisted badge position there.
15. **Timing/ruler audit.** The baseline ruler began at zero, and the clock's duration was correctly derived from clip ends rather than a separate source-duration field. The reported arbitrary four-minute initial offset was not reproduced. The scroll viewport could, however, remain away from the playhead after seeking or zoom changes. Initial timeline scroll is now reset per project, and off-screen playheads are brought into view after larger seeks, zoom changes, and during playback.
16. **Synchronization.** Preserved the single `PlaybackClock`, existing source offset/speed conversion, preview seek slider, and ruler/playhead slider. Lane seeking now shares the same coordinate utility as dropping. Media current time, playhead, ruler clicks, pointer playhead dragging, and playback advancement are tested against real video/audio elements. No second clock was added.
17. **Track headers.** Layout and controls stay intact. Names and media icons still identify tracks; lock, visibility, and mute controls remain where applicable. Browser checks retain row/header alignment and verify the created Audio 1 track.
18. **Other fixes.** Thumbnail failure fallback, readiness checks, clip-count/track-count/asset-count and timeline-duration guards, refreshed metadata persistence, explicit source drag identity, and timeline movement/end-trim bounds. Long project names retain the constrained input width and now expose their full name through its hover title. AI header/content/composer scrolling remains unchanged and covered by the existing growing-conversation checks.
19. **Shared UI reused.** `AppButton`, `AppDropdown`, `AppTooltip`, `AppMediaCard`, `AppInput`, `AppSlider`, `AppScrollArea`, `AppPopover`, `AppContextMenu`, dialogs/file input, sidebar items, and existing theme controls. `PreviewZoom` is a feature-specific composition, not a generic replacement primitive.
20. **Changed files.** Studio `components/theme-provider.tsx`, `next.config.ts`; editor `components/EditorToolbar.tsx`, `hooks/useEditor.tsx`, `media/MediaItem.tsx`, `media/MediaPanel.tsx`, `preview/PlaybackControls.tsx`, `preview/PreviewCanvas.tsx`, new `preview/PreviewZoom.tsx`, `stores/editor-store.ts`, `timeline/Timeline.tsx`, `timeline/TimelineClip.tsx`, new `utils/timeline.ts`; scripts `test-editor.mjs`, `test-workspace.mjs`; shared UI `src/index.ts`, new `src/components/AppThemeProvider.tsx`, `src/styles/theme.css`; this report.
21. **Lint.** Studio and shared UI lint passed.
22. **Typecheck.** Studio and shared UI typecheck passed.
23. **Production build.** Passed with `MAIN_APP_URL=https://app.blynta.com pnpm --filter @blynta/studio build`, including compilation, TypeScript, and static page generation. The command-only production URL does not modify environment files.
24. **Limitations.** No group media selection/drag, cross-track pointer movement, ripple editing, or new export engine was introduced. The existing one-hour timeline, 150-clip, 20-track, and 200-asset limits remain. API transport in the browser suite is mocked; playback uses generated playable WebM/WAV fixtures. Production storage/signing/rendering and authenticated live account behavior are not exercised by that suite. Backend/auth source remains unchanged.

The existing pure editor/auth suite passed, including new insertion, metadata, collision, missing/custom tracks, limits, and undo/redo assertions. The expanded Playwright suite passed native sequential video/image/audio drag flows; insertion feedback; locked/processing media rejection; thumbnail fallback; clip repositioning and history; save/reload persistence; actual video/audio current-time synchronization; pointer playhead dragging; scrolled drops; all preview zoom levels, Ctrl-wheel, and no zoom-induced autosave; reduced motion; real theme switching and dashboard/editor navigation, refresh, and system mode. Existing responsive geometry, track-header alignment, growing AI history with anchored composer, resize persistence, and export UI checks remain.

Visually reviewed the two-column library and AI CTA in light/dark themes, native drag insertion feedback, populated multi-asset timeline, and compact media badges.
